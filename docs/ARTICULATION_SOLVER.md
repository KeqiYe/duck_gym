# Articulation 数学方案建议

日期：2026-09-09。状态：技术建议，等待讨论；未实现、未做 CPU/CUDA 性能比较。原生 CUDA 与完整 CPU 求解已由用户确认，本文算法尚未确认。

## 1. 推荐组合与依据

**约化坐标 + Featherstone 空间代数 + CRBA/RNEA + 小型 Cholesky 分解 + SAP 类速度层柔性接触 + 带线搜索的 Newton + 流形上的位置更新。**

这是针对当前 MicroDuck 的起步方案：已检查的 `robot_allcollisions.xml` 有 14 个 hinge、1 个自由基座，无有效 equality 或 tendon 条目。因此该模型是关节树，广义速度维度为 20；选用其他模型变体时必须重新检查。

| 方案 | 优点 | 本项目定位 |
| --- | --- | --- |
| 约化坐标 + CRBA/RNEA + 矩阵分解 | 质量矩阵可检查，接触与隐式控制容易统一，小系统便于 CPU/GPU 对照 | 首版推荐 |
| 约化坐标 + ABA | 树形无约束前向动力学为线性复杂度，不必显式形成质量矩阵 | 后续独立实现，用于交叉验证与性能比较 |
| 最大坐标 + 关节约束迭代 | 刚体和约束组织统一，适合一般连接拓扑 | 当前关节树会增加未知量与关节约束残差，不作为首版主线 |
| PBD/XPBD | 位置约束与柔顺性实现直接 | 可作对照；当前更关注力矩驱动动力学、接触力与数值可验证性 |

CRBA、RNEA 与 ABA 属于不同计算环节；“采用 Featherstone 方法”并不等于必须从 ABA 开始。算法原始参考：[Featherstone Spatial_v2](https://royfeatherstone.org/spatial/v2/)。

## 2. 状态和动力学

取基座位置、单位四元数和 14 个关节角作为配置，基座六维速度和关节角速度作为广义速度：

\[
q=(p_B,Q_B,\theta),\qquad n_q=3+4+14=21,\qquad n_v=6+14=20.
\]

姿态的四元数存储不增加物理自由度，不能直接把 21 维配置与 20 维速度相加。空间运动向量建议统一采用角速度在前、线速度在后的顺序，明确每个量所在坐标系，并在导入与 rsl-rl 边界转换。

连续时间动力学：

\[
M(q)\dot v+b(q,v)=S^Tu+f_{\rm other}+J(q)^Tf_c.
\]

其中 \(S\in\mathbb R^{14\times20}\) 选择受驱关节速度，\(u\) 为关节力矩，\(b\) 包括科氏、离心和重力项，\(f_{\rm other}\) 为其他广义力，\(f_c\) 为接触力。自由基座不施加虚构的驱动力。

- **RNEA** 求偏置项：在无外部力、广义加速度为零的条件下求逆动力学；浮动基座的坐标约定须一致。
- **CRBA** 装配 \(M\)，加入选定模型的关节 armature 等惯性贡献。
- 分解 \(M=LL^T\)，通过前后代入求解；不用显式求逆。非正定失败应检查模型/坐标/精度，不能靠任意对角扰动掩盖模型错误。

当前 \(M\) 为 \(20\times20\)。稠密矩阵分解一般是三次复杂度，ABA 的无约束求解是线性复杂度；这里选择显式小矩阵是为了接触、控制和校验的统一，不是在未测量前宣称它比 ABA 更快。

## 3. 接触与时间离散

ABA 或 CRBA 得到的自由运动仍需满足足底接触、摩擦与关节限位。建议主线使用柔性接触的速度层离散；接触几何与 Jacobian 在单步内冻结，单步求解不能防止未检测到的穿透，需要接触生成策略及时间步收敛检查。

先定义无接触预测速度 \(v^*\) 和对称正定的有效惯性 \(A\)。只有显式光滑力时：

\[
A=M(q_k),\qquad A(v^*-v_k)=h(S^Tu+f_{\rm other}-b).
\]

然后求接触冲量 \(\gamma\) 与更新速度：

\[
A(v_{k+1}-v^*)=J^T\gamma.
\]

这里 \(\gamma\) 是冲量，\(f_c\) 是力；不能混淆或漏掉时间步 \(h\)。

### 推荐的接触数学框架

SAP 类模型把接触写成速度空间中的凸优化。下面是用于明确接口的正则化锥接触表达，不是完整复刻 Drake 的参数选择：

\[
\min_v F(v)=\tfrac12(v-v^*)^TA(v-v^*)+\sum_i\ell_i(J_i v),
\]

\[
\ell_i(w)=\max_{\gamma_i\in K_i}
\left[-\gamma_i^T(w-\hat w_i)-\tfrac12\gamma_i^TR_i\gamma_i\right],
\qquad R_i\succ0.
\]

\(K_i=\{\gamma_n\ge0,\;\|\gamma_t\|_2\le\mu_i\gamma_n\}\) 是接触冲量摩擦锥，法向正方向为分离；\(\hat w_i\) 是接触偏置速度，\(R_i\) 表示柔顺性和离散正则化。参数必须由时间步、间隙、刚度与耗散模型一致确定，不能仅当作任意收敛调节量。

该局部问题等价于加权锥投影：

\[
\gamma_i(v)=\Pi_{K_i}^{R_i}\!\left[-R_i^{-1}(J_i v-\hat w_i)\right],
\qquad \nabla F=A(v-v^*)-\sum_iJ_i^T\gamma_i(v).
\]

只有法向时，退化为 \(\gamma_n=\max(0,(\hat w_n-w_n)/R_n)\)，可先用于验证接触符号与静态载荷，再加入摩擦。

选择带线搜索的 Newton，在锥边界使用一致的分段/广义导数；有效 Hessian 为 \(A+\sum_i J_i^TG_iJ_i\)，其中 \(G_i\succeq0\)。对于单个 20 维机器人和静态地面，每次 Newton 线性求解仍是 20 维，接触数量增加的是组装成本；加入可动外物会扩大系统。

该模型是**柔性、正则化的摩擦接触近似**，并非严格硬接触 Signorini–Coulomb 方程的精确求解；凸锥近似可能产生滑动时的法向耦合等偏差，需要静态滑移、斜面和脚底稳定性验证。改变接触模型时应明确记录，不能只更换求解器名称。

参考：[SAP 论文](https://arxiv.org/abs/2110.10107)、[Drake 离散接触说明](https://drake.mit.edu/doxygen_cxx/group__mbp__discrete.html)、[SAP 求解器说明](https://github.com/RobotLocomotion/drake/blob/master/multibody/contact_solvers/sap/sap_solver.h)。MuJoCo 也采用约化坐标与凸柔性约束，但其连续时间和离散细节不同：[MuJoCo computation](https://mujoco.readthedocs.io/en/stable/computation/index.html)。

## 4. 积分与电机刚性

首版建议先更新速度，再用新速度更新位置；基座旋转采用 SO(3) 指数映射/对应单位四元数乘法。若基座角速度采用 body frame，\(R_{k+1}=R_k\exp(h[\omega_{k+1}]_\times)\)；若采用 world frame，乘法顺序相反。四元数归一化，位置更新须使用一致的线速度坐标系。

较强 PD 不应直接配任意大时间步。对无饱和的线性关节 PD，在单步冻结质量矩阵与其他光滑项时，可以隐式处理：

\[
A=M+hS^TK_dS+h^2S^TK_pS,
\]

\[
Av^*=Mv_k+h\{S^TK_p(\theta_{\rm ref}-\theta_k)+f_{\rm other}-b\}.
\]

接触更新和 Newton 目标必须使用同一个 \(A\)。此式假设 \(K_p,K_d\succeq0\)、目标在该步保持不变；不能直接套用到带力矩饱和、齿隙、负载摩擦或 BAM 非线性执行器，后者需另做离散模型。

## 5. CPU/CUDA 与验证顺序

CPU 和 CUDA 实现同一数学模型，完整支持动力学、接触、限位、积分和重置。CPU 保留 FP64 参考，CPU FP32 对 CUDA FP32 分离精度与后端差异；不要求长期轨迹逐位相同。

GPU 先从不同环境间并行获得吞吐，再测量每环境一个 warp 或 block 的方案。矩阵规模小并不自动保证快：寄存器占用、接触数量、线搜索分歧和内存访问必须实测。保留最大迭代预算和残差/失败状态，不把“迭代次数用完”当成收敛。

建议依次验证：

1. 变换、空间惯性、单/双摆；浮动基座自由运动。质量矩阵对称正定，动能与逐刚体计算一致。
2. 随机状态的 RNEA/CRBA 前逆动力学闭合、Jacobian 与有限差分一致；以后用独立 ABA 交叉验证。
3. 无摩擦落体接触、静态承重、滑块与斜面；检查冲量、穿透和残差。
4. MicroDuck 多点足底接触、单脚支撑、关节限位与高增益控制；不以单个足底质心点代替整个支撑面。
5. 时间步减半、CPU/CUDA 同精度对照和端到端批量性能；光滑无耗散系统检查能量漂移趋势，不能要求一阶积分严格守恒。

首版阶段顺序为：自由动力学 → 法向接触 → 摩擦与限位 → MicroDuck 支撑 → 批量训练。ABA 是未来基准候选；当前没有性能证据决定何时替换。
