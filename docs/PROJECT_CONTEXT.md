# MicroDuck 训练引擎：工作上下文

更新日期：2026-09-09。状态：需求与路线草稿；已确认要求如下，技术建议仍需验证。

## 1. 项目目标与当前阶段

为 **Pollen Robotics MicroDuck** 自研物理仿真与训练环境，支持 **CPU/CUDA**，接入 **rsl-rl** 训练策略。尽可能从一开始采用支持多厂商 GPU 的方案，必要时先实现 CUDA。

当前阶段是共同建立工作上下文。实施建议见 [技术路线](TECHNICAL_PLAN.md)，实际能力以代码和验证记录为准。

## 2. 已确认要求

| 主题 | 已确认内容 |
| --- | --- |
| 机器人 | [Pollen Robotics MicroDuck](https://pollen-robotics.com/microduck/)，使用官方开源资产 |
| 引擎 | 自己实现仿真引擎，并接入 rsl-rl |
| 后端 | CPU/CUDA 均需支持；多厂商 GPU 从一开始可行则优先，必要时先兼容 CUDA |

| 运行位置 | 仿真与训练通过 SSH 在远端运行 |
| 远端顺序 | 优先 `gpu`，连接不到时回退 `delltower` |
| 可视化 | 完整体现机器人资产，让人一眼认出是 MicroDuck |
| 版本管理 | 使用 Git 管理代码、配置与文档 |

用户最初提出“纯 CUDA”，随后明确“如果可以一开始就能支持多厂商 GPU 那最好，要是不行那就先兼容 CUDA”。以这一后续优先级为准，具体并行编程技术尚待验证。

## 3. 已核实的现状

- 项目目录：`/Volumes/External/duck_gym`。初次检查为空，目前已建立文档，并初始化本地 Git 仓库，分支为 `main`。
- 尚无仿真、训练或查看器实现；未安装项目依赖、启动训练或部署远端项目。
- 本机为 `Darwin arm64`；`ssh delltower` 可达，系统为 Linux x86_64，GPU 为 NVIDIA GeForce RTX 4090。
- 本机直连 `gpu` 失败；经 `delltower` 执行 `ssh gpu` 时主机名解析失败。目前按规则使用 `delltower`。详见 [探测记录](REMOTE_EXECUTION.md)。
- 官方运行时仓库为 [microduck](https://github.com/pollen-robotics/microduck)，模型与训练参考位于 [microduck_rl](https://github.com/pollen-robotics/microduck_rl)。上游训练基于 mjlab / MuJoCo Warp，可作为资产与行为参考。
- 已读取上游目录树、机器人配置和完整模型 XML，记录版本及网格引用；尚未下载全部网格或渲染模型。详见 [资产清单](microduck_asset_manifest.json)。

## 4. 技术路线建议与边界

建议以 **C++ + Kokkos** 编写自研求解器，首先验证 CPU 和 NVIDIA CUDA 后端，为 AMD HIP、Intel SYCL 等后端保留可移植实现。采用前验证编译工具链、代表性算子和 PyTorch 张量互操作；不能满足要求时，记录原因并回退 C++/CUDA。

Kokkos 负责并行执行和内存抽象；动力学、接触、约束、积分与任务环境由本项目实现；rsl-rl 负责策略学习。这是根据用户目标形成的工程建议，尚未形成实现。

可视化建议使用独立浏览器查看器：远端计算连杆姿态，Mac 显示官方网格与材质。完整外观和碰撞模型分别管理，训练可无窗口运行。

CPU/CUDA 是明确要求，多厂商是优先方向。尚未测试的后端不能标成已支持。Apple GPU 加速、实机部署和通用机器人引擎均未被确定为首阶段要求。

## 6. 待定问题

1. 首个行为：站立、平地速度跟踪或其他动作，以及对应验收指标。
2. Kokkos 可行性、版本与 C++ 标准；rsl-rl / PyTorch 的锁定版本。
3. 模型变体、执行器模型、碰撞范围、接触算法和数值容差。
4. 是否需要对齐官方策略的观测与动作约定，以及是否计划实机部署。
5. `gpu` 的有效地址或别名配置；暂不阻塞 `delltower` 路线。
6. 远端项目目录、隔离环境与代码同步方式。
