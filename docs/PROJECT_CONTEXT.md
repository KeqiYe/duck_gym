# MicroDuck 训练引擎：工作上下文

更新日期：2026-09-09。状态：CPU/CUDA 与刚体 AVBD 主线已确认；具体参数和实现仍待验证。

## 1. 项目目标与当前阶段

为 **Pollen Robotics MicroDuck** 自研物理仿真与训练环境，支持 **CPU/CUDA**，接入 **rsl-rl** 训练策略。当前采用原生 C++/CUDA，同时保留完整 CPU 求解；多厂商 GPU 暂缓。

当前阶段是共同建立工作上下文。已确定的物理主线为刚体 AVBD，详见 [技术路线](TECHNICAL_PLAN.md) 与 [求解器方案](ARTICULATION_SOLVER.md)；实际能力以代码和验证记录为准。

## 3. 已选技术路线与边界

已确定采用 **原生 C++/CUDA + CPU 求解**。建议 CPU/CUDA 共享数学定义、模型和小型算子，执行调度及存储布局可分别优化。两条路径都应完整支持动力学、接触、积分与重置。CPU 代码允许在 Mac 本地运行；GPU 代码必须先同步到所选远端工作目录，再远端编译运行。源码副本、构建与结果分别存放，详见 [运行约定](REMOTE_EXECUTION.md)。

动力学、接触、约束、积分与任务环境由本项目实现；rsl-rl 负责策略学习。物理主线已选定 **刚体 AVBD**：每个连杆采用独立刚体位姿，以六维局部块求解，通过增广拉格朗日处理关节，并在同一框架内处理接触与摩擦。详见 [求解器方案](ARTICULATION_SOLVER.md)。

可视化只需覆盖 **推理模式或单个 CPU 环境**，以 Mac 本地运行、显示完整 MicroDuck 为目标。远端 GPU 批量训练采用无窗口模式，训练期实时渲染和远端姿态流不属于当前要求。训练后的策略及所需配置可传回 Mac，在 CPU 环境内推理并可视化。

`num_envs` 表示并行独立仿真环境的个数；单 CPU env 表示 CPU 求解后端加 `num_envs=1`，不表示单核/单线程，也不限制 CPU 后端只能运行一个环境。环境数量、求解设备和渲染开关分别配置。不同环境具有独立状态、接触和重置状态，可共享只读机器人资产。

CPU/CUDA 是明确要求。尚未测试的后端不能标成已支持。Apple GPU 加速、实机部署和通用机器人引擎均未被确定为首阶段要求。

## 5. 待定问题

1. 首个行为：站立、平地速度跟踪或其他动作，以及对应验收指标。
2. C++ 标准、CUDA Toolkit、rsl-rl / PyTorch 的锁定版本，以及 CPU/CUDA 共享代码方式。
3. AVBD 具体版本与推导、乘子/惩罚调度、接触摩擦离散、时间步、迭代预算与容差，以及模型变体、执行器和碰撞范围。
4. 是否需要对齐官方策略的观测与动作约定，以及是否计划实机部署。
5. `master172` 的实际 SSH 连接与 GPU/工具链环境，以及两处指定工作目录的可用性。
6. 隔离环境、具体同步/运行脚本及运行元数据格式；工作根目录和先同步后编译运行的顺序已确定。
