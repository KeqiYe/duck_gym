# 运行约定：本地 CPU 与远端 GPU

更新日期：2026-09-09。状态：运行位置、工作根目录与执行顺序已由用户明确；本轮仅更新文档，未同步代码、创建远端目录或运行计算任务。

## 1. 每次运行的选择规则

- **纯 CPU 代码可以在 Mac 本地编译运行**，包括 CPU 求解、单元测试、资产处理和本地渲染测试；不再要求所有仿真代码都远端运行。
- **GPU/CUDA 代码在 SSH 远端编译运行**，首选 `master172`，连接不可用时回退 `delltower`。本地可运行查看器，但不能把 Mac 的 Apple GPU 作为 CUDA 设备。
- 每次远端运行前，**先通过 scp 或 rsync 同步本次代码到所选主机的项目工作目录，核对同步完成，再在目标主机编译、运行**。
- 配置、启动脚本和运行必需资产随代码同步或按固定版本核验；不能只同步入口脚本而保留陈旧依赖文件。
- 运行前检查连接、目录、GPU、编译器、Toolkit 与依赖。历史连接失败不代表永久不可用，SSH 成功也不代表 CUDA 环境已就绪。

## 2. 指定工作区

用户指定的工作根目录如下；在各根目录下统一使用 `duck_gym/` 作为本项目工作目录，避免与其他项目混用。

| 主机 | 工作根目录 | 本项目工作目录 |
| --- | --- | --- |
| master172（首选） | `/public/yekq6Data/codex` | `/public/yekq6Data/codex/duck_gym` |
| delltower（回退） | `/home/yekeqi/Documents/HDD1/codex` | `/home/yekeqi/Documents/HDD1/codex/duck_gym` |

每台机器采用相同结构：

```text
duck_gym/
  source/                 # 完整项目源码副本，目录根对应本地 Git 项目根
  build/<backend-config>/ # 在目标主机生成的构建文件与二进制
  runs/<run-id>/          # 每次运行的日志、配置快照、轨迹、模型及模拟结果
```

`source/` 包含项目自己的目录结构；它不是仅用于复制项目内部的 `src/` 文件夹。不同后端或不兼容的工具链使用不同构建子目录，各次运行使用独立结果目录。依赖缓存或隔离环境如需项目内存放，也应位于本项目工作目录下。

源码副本、编译目录和模拟结果均保留在以上指定工作区。具体子目录是本项目的组织约定，尚未在远端创建；目录的存在性和权限在首次使用时检查。

本地 CPU 运行直接使用 `/Volumes/External/duck_gym` 中的代码；构建与结果分别放入本项目的 `build/` 和 `runs/`，无需为了本地 CPU 测试额外同步远端。Mac 与 Linux 的构建产物不能混用。

## 3. 每次远端运行的执行顺序

1. **选主机**：检查首选 master172 的连接；不可连接时选 delltower，并记录回退原因。进入该主机指定的 `duck_gym/` 工作区。
2. **确认本次版本**：以本地 Git 工作区为源码来源，记录提交 ID；若有未提交修改，记录 dirty 状态及本次源码差异或内容清单，不能只用提交 ID 声称复现了修改后的代码。
3. **先同步**：用 scp 或 rsync 将当前代码、配置、启动脚本及必要资产送到 `source/`。可使用增量同步；同步成功且所需文件版本一致后才能继续。同步不覆盖 `build/` 和 `runs/`。
4. **在远端编译**：从同步后的 `source/` 配置构建，产物写到对应 `build/<backend-config>/`。同一工具链可增量构建；不能直接拿旧二进制跳过构建检查，也不能拿 Mac 二进制到 Linux 运行。
5. **在远端运行**：以该源码、构建与配置执行任务，明确输出目录为新的 `runs/<run-id>/`，保存日志、配置快照、模拟结果或训练模型。
6. **记录并回收结果**：记录实际主机、源码版本/差异、资产版本、编译器与依赖、CPU/CUDA 后端、设备、随机种子和运行命令。需要本地检查时，将选定结果同步回本地 `runs/`，保留对应运行标识。

若启动的是无需编译的 Python 脚本，同步顺序不变；在目标主机核对依赖后运行，涉及的原生扩展仍需在目标环境正确构建。运行期间更改代码时，后续任务须重新同步和构建，避免版本混淆。

长任务使用持久会话或作业机制，记录 PID/作业 ID 与日志路径。SSH 中断后先查询已有作业状态，避免在另一台机器重复启动。

GPU 多 env 训练无窗口运行。需要查看策略行为时，将模型、观测归一化统计及所需配置同步回 Mac，使用 CPU 后端、`num_envs=1` 运行推理与本地可视化；也可本地查看单 CPU env 的测试。当前不要求远端实时渲染或姿态流服务。
