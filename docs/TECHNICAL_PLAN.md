# 技术设计：AVBD、训练接口与可视化

本文件维护数学与接口设计；开发顺序和实现状态统一见 [开发路径](DEVELOPMENT_ROADMAP.md)，运行规则见 [AGENTS.md](../AGENTS.md)。

## 1. 模块职责与资产

自研引擎负责资产导入、刚体动力学、碰撞与接触、关节约束、控制、积分、重置及批量环境；rsl-rl 负责策略学习，Python 用于配置、资产处理与训练入口。

官方资产来源、提交、模型路径、网格列表及许可元数据统一见 [资产清单](microduck_asset_manifest.json)。导入时核对并保留原始许可和署名，软件许可不能直接套用于 3D 模型。

- 区分外观网格与碰撞几何；STL 顶点不作为独立动力学粒子。
- 明确支持的 MJCF 子集，对不支持的语义显式报错。`robot_walk.xml` 与场景变体需比较后选择，执行器配置可参考上游 `microduck_constants.py`。
- 动作维度按实际模型和执行器映射确定，不直接以官网电机数推导。
- MuJoCo 承担资产显示和独立对照；对照时统一模型参数、初始条件、控制输入、时间步和误差指标，吞吐对比注明精度与测试条件。

## 2. 刚体 AVBD 数学

采用 VBD 的刚体扩展及 AVBD 的约束处理，每个连杆作为一个六维刚体块。具体离散公式、参数和收敛阈值需在实现前推导并验证。

### 状态表示

已检查的 `robot_allcollisions.xml` 包含 15 个刚体、14 个 hinge 和 1 个自由基座，无有效 equality 或 tendon 条目。该结论仅适用于 [资产清单](microduck_asset_manifest.json) 中记录的版本，其他变体须重新检查。

每个刚体保存质心位置、单位四元数、线速度、角速度、质量和质心惯性。求解使用局部增量：

\[
\delta z_i=(\delta x_i,\delta\theta_i)\in\mathbb R^6.
\]

共有 90 个速度自由变量；14 个 hinge 各施加 5 个独立约束，因而物理自由度为：

\[
15\times6-14\times5=20.
\]

四元数的 4 维存储不增加旋转自由度。局部块仍是六维，不对四元数四个分量做无约束更新。

旋转通过 SO(3) 指数映射或对应四元数乘法更新，明确 world/body frame 与乘法顺序；固定四元数存储顺序、角速度坐标系、单位及惯性参考点。模型 link 原点与质心原点之间的偏移必须保留。

### 关节、限位和电机

- hinge 以 3 个位置条件保持两侧锚点重合，以 2 个独立角度条件保持转轴对齐，保留绕轴旋转。
- 从相邻刚体的相对姿态提取关节角和速度，统一零位、符号、周期处理与关节索引，用于观测、控制及限位。
- 限位属于单边约束；电机按选定执行器模型施加有界作用，不把策略动作直接解释为刚体位置覆盖或无限强度位置约束。
- 内部关节电机的作用与反作用须一致；自由基座不施加虚构的驱动力。
- 时间步、惯性/armature、阻尼、力矩上限和非线性执行器模型都需明确。BAM、齿隙等扩展不直接套用简单线性 PD 公式。

### AVBD 数学结构

原始 VBD 以分块坐标下降求隐式 Euler 的变分问题；AVBD 引入增广拉格朗日约束处理，支持刚体关节、接触及摩擦。对于等式关节约束，可用下式表达其结构：

\[
\mathcal L(z,\lambda)=E_{\rm inertia}(z)+E_{\rm soft}(z)
+\sum_j\left[\lambda_j^TC_j(z)+\tfrac12C_j(z)^TP_jC_j(z)\right].
\]

固定其他块，构造当前刚体的局部线性化系统：

\[
H_{ii}\delta z_i=-g_i,
\]

求解六维增量并更新位姿。普通等式增广拉格朗日的乘子更新可示意为：

\[
\lambda_j\leftarrow\lambda_j+P_jC_j(z).
\]

这些公式用于说明分块与约束结构，不是完整 AVBD 算法规范。实现前必须确定论文对应的乘子调度、刚度递增、松弛、warm-start、局部矩阵构造和数值保护，不能仅凭上述更新式宣称完成 AVBD。

刚体旋转的惯性能量、坐标变换及陀螺项需要一致推导；平移顶点能量不能直接复制到旋转变量。局部矩阵的对称性、正定化或残差线性化策略必须明确，不能默认所有六维系统都可直接 Cholesky 分解。

### 接触、摩擦与时间推进

接触和关节进入同一 AVBD 迭代框架。法向接触采用单边约束和相应有界乘子处理；摩擦按法向载荷限制切向作用。不能对接触直接使用无界的等式乘子更新，具体摩擦离散和投影规则仍待锁定。

接触生成独立负责碰撞候选、接触点、法线、间隙和稳定标识。单步迭代不能弥补漏检；需验证时间步、子步和接触更新策略。足底保留能表达支撑面积和接触力矩的接触表示。

以选定刚体 AVBD 的隐式 Euler 离散为基础，预测位姿、迭代更新位姿与约束，再按一致规则恢复速度。位姿与速度更新须对应同一个时间步，避免重复推进时间。

记录乘子表示的是力还是冲量，并显式处理时间步缩放。接触新增、消失、环境重置时正确管理缓存；不能沿用失效的乘子、摩擦状态或接触索引。

## 3. CPU/CUDA 实现

CPU 使用原生 C++，GPU 使用 CUDA C++。两者完整支持动力学、约束、控制和重置，共享数学定义与可比较的迭代规则。每个环境独立维护刚体、乘子、接触和重置状态，可共享只读资产，不发生跨环境物理耦合。

- CPU 保留 FP64 参考；CPU FP32 对 CUDA FP32 用于分离实现差异与精度差异。
- CUDA 优先利用不同环境并行；环境内部使用无冲突的刚体块调度，如图着色。同色块之间须无共享耦合约束，颜色之间保持必要同步。
- 接触改变约束图时重新验证调度。静态关节树的着色不能自动保证新增自碰撞边也无冲突。
- 每块一个线程、warp 或 block 是待测实现选项，依据局部矩阵开销、寄存器占用、访存与同步成本决定。
- 设定最大迭代预算并返回残差和失败状态；迭代预算耗尽不等于收敛。性能比较应使用相同精度目标与场景。
- GPU 状态尽量留在设备，与 PyTorch 交互须检查缓冲区所有权和 stream/event 同步。

## 4. pybind 与 rsl-rl 接口

- 通过 pybind 暴露引擎接口；锁定 [rsl-rl](https://github.com/leggedrobotics/rsl_rl) 版本后，按实际接口定义 reset/step、观测、动作、奖励、终止与超时信息。
- `num_envs` 对应张量的环境批维，终止与重置按环境分别处理。
- 明确 dtype、设备、关节顺序、单位、坐标系、四元数顺序和控制周期。
- CPU 与 CUDA 分别验证完整引擎到 PyTorch/rsl-rl 的数据传递。CUDA 仿真与策略尽量在同一 GPU，验证共享缓冲区生命周期及 stream/event 同步。
- 检查 NaN、环境重置、终止/超时、模型保存加载与确定条件下的回放。

## 5. MuJoCo 可视化接口

查看器加载完整外观网格、材质和模型层级，显示自研引擎输出的连杆姿态。状态映射需明确 link 原点与质心偏移、坐标系、四元数及关节顺序；显示适配不能用 MuJoCo 动力学步进覆盖自研求解结果。

在 Mac 本地 CPU 单环境中先实现状态显示，再用于策略推理。CPU 求解与本机图形渲染分别配置，查看器不依赖 CUDA；当前无需训练期实时渲染、远端姿态流或同时显示全部训练环境。
