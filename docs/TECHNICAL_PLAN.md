# 技术设计：AVBD、训练接口与可视化

本文件维护数学与接口设计；开发顺序和实现状态统一见 [开发路径](DEVELOPMENT_ROADMAP.md)，运行规则见 [AGENTS.md](../AGENTS.md)。

## 1. 模块职责与资产

自研引擎负责资产导入、刚体动力学、碰撞与接触、关节约束、控制、积分、重置及批量环境；rsl-rl 负责策略学习，Python 用于配置、资产处理与训练入口。

官方资产来源、提交、模型路径、网格列表及许可元数据统一见 [资产清单](microduck_asset_manifest.json)。导入时核对并保留原始许可和署名，软件许可不能直接套用于 3D 模型。

- 区分外观网格与碰撞几何；STL 顶点不作为独立动力学粒子。
- 明确支持的 MJCF 子集，对不支持的语义显式报错。`robot_walk.xml` 与场景变体需比较后选择，执行器配置可参考上游 `microduck_constants.py`。
- 动作维度按实际模型和执行器映射确定，不直接以官网电机数推导。
- MuJoCo 承担资产显示和独立对照；对照时统一模型参数、初始条件、控制输入、时间步和误差指标，吞吐对比注明精度与测试条件。

## 2. 刚体 AVBD 数学

采用 VBD 的刚体扩展及 AVBD 的约束处理，每个连杆作为一个六维刚体块。当前 CPU 首版的离散与参数见下节；后续变更须重新验证。

### 状态表示

已检查的 `robot_allcollisions.xml` 包含 15 个刚体、14 个 hinge 和 1 个自由基座，无有效 equality 或 tendon 条目。该结论仅适用于 [资产清单](microduck_asset_manifest.json) 中记录的版本，其他变体须重新检查。

每个刚体保存质心位置、单位四元数、线速度、角速度、质量和质心惯性。求解使用局部增量：

\[
\delta z_i=(\delta x_i,\delta\theta_i)\in\mathbb R^6.
\]

共有 90 个速度自由变量；14 个 hinge 各施加 5 个独立约束，因而物理自由度为：

\[
15\times6-14\times5=20.
\]

四元数的 4 维存储不增加旋转自由度。局部块仍是六维，不对四元数四个分量做无约束更新。

旋转通过 SO(3) 指数映射或对应四元数乘法更新，明确 world/body frame 与乘法顺序；固定四元数存储顺序、角速度坐标系、单位及惯性参考点。模型 link 原点与质心原点之间的偏移必须保留。

### 关节、限位和电机

- hinge 以 3 个位置条件保持两侧锚点重合，以 2 个独立角度条件保持转轴对齐，保留绕轴旋转。
- 从相邻刚体的相对姿态提取关节角和速度，统一零位、符号、周期处理与关节索引，用于观测、控制及限位。
- 限位属于单边约束；电机按选定执行器模型施加有界作用，不把策略动作直接解释为刚体位置覆盖或无限强度位置约束。
- 内部关节电机的作用与反作用须一致；自由基座不施加虚构的驱动力。
- 时间步、惯性/armature、阻尼、力矩上限和非线性执行器模型都需明确。BAM、齿隙等扩展不直接套用简单线性 PD 公式。

### AVBD 数学结构

原始 VBD 以分块坐标下降求隐式 Euler 的变分问题；AVBD 引入增广拉格朗日约束处理，支持刚体关节、接触及摩擦。对于等式关节约束，可用下式表达其结构：

\[
\mathcal L(z,\lambda)=E_{\rm inertia}(z)+E_{\rm soft}(z)
+\sum_j\left[\lambda_j^TC_j(z)+\tfrac12C_j(z)^TP_jC_j(z)\right].
\]

固定其他块，构造当前刚体的局部线性化系统：

\[
H_{ii}\delta z_i=-g_i,
\]

求解六维增量并更新位姿。普通等式增广拉格朗日的乘子更新可示意为：

\[
\lambda_j\leftarrow\lambda_j+P_jC_j(z).
\]

这些公式用于说明分块与约束结构，不是完整 AVBD 算法规范。实现前必须确定论文对应的乘子调度、刚度递增、松弛、warm-start、局部矩阵构造和数值保护，不能仅凭上述更新式宣称完成 AVBD。

刚体旋转的惯性能量、坐标变换及陀螺项需要一致推导；平移顶点能量不能直接复制到旋转变量。局部矩阵的对称性、正定化或残差线性化策略必须明确，不能默认所有六维系统都可直接 Cholesky 分解。

### 接触、摩擦与时间推进

接触和关节进入同一 AVBD 迭代框架。法向接触采用单边约束和相应有界乘子处理；摩擦按法向载荷限制切向作用。不能对接触直接使用无界的等式乘子更新，具体摩擦离散和投影规则仍待锁定。

接触生成独立负责碰撞候选、接触点、法线、间隙和稳定标识。单步迭代不能弥补漏检；需验证时间步、子步和接触更新策略。足底保留能表达支撑面积和接触力矩的接触表示。

以选定刚体 AVBD 的隐式 Euler 离散为基础，预测位姿、迭代更新位姿与约束，再按一致规则恢复速度。位姿与速度更新须对应同一个时间步，避免重复推进时间。

记录乘子表示的是力还是冲量，并显式处理时间步缩放。接触新增、消失、环境重置时正确管理缓存；不能沿用失效的乘子、摩擦状态或接触索引。

## 3. CPU/CUDA 实现

CPU 使用原生 C++，GPU 使用 CUDA C++。两者完整支持动力学、约束、控制和重置，共享数学定义与可比较的迭代规则。每个环境独立维护刚体、乘子、接触和重置状态，可共享只读资产，不发生跨环境物理耦合。

- CPU 保留 FP64 参考；CPU FP32 对 CUDA FP32 用于分离实现差异与精度差异。
- CUDA 优先利用不同环境并行；环境内部使用无冲突的刚体块调度，如图着色。同色块之间须无共享耦合约束，颜色之间保持必要同步。
- 接触改变约束图时重新验证调度。静态关节树的着色不能自动保证新增自碰撞边也无冲突。
- 每块一个线程、warp 或 block 是待测实现选项，依据局部矩阵开销、寄存器占用、访存与同步成本决定。
- 设定最大迭代预算并返回残差和失败状态；迭代预算耗尽不等于收敛。性能比较应使用相同精度目标与场景。
- GPU 状态尽量留在设备，与 PyTorch 交互须检查缓冲区所有权和 stream/event 同步。

## 4. pybind 与 rsl-rl 接口

- 通过 pybind 暴露引擎接口；锁定 [rsl-rl](https://github.com/leggedrobotics/rsl_rl) 版本后，按实际接口定义 reset/step、观测、动作、奖励、终止与超时信息。
- `num_envs` 对应张量的环境批维，终止与重置按环境分别处理。
- 明确 dtype、设备、关节顺序、单位、坐标系、四元数顺序和控制周期。
- CPU 与 CUDA 分别验证完整引擎到 PyTorch/rsl-rl 的数据传递。CUDA 仿真与策略尽量在同一 GPU，验证共享缓冲区生命周期及 stream/event 同步。
- 检查 NaN、环境重置、终止/超时、模型保存加载与确定条件下的回放。

## 5. MuJoCo 可视化接口

查看器加载完整外观网格、材质和模型层级，显示自研引擎输出的连杆姿态。状态映射需明确 link 原点与质心偏移、坐标系、四元数及关节顺序；显示适配不能用 MuJoCo 动力学步进覆盖自研求解结果。

在 Mac 本地 CPU 单环境中先实现状态显示，再用于策略推理。CPU 求解与本机图形渲染分别配置，查看器不依赖 CUDA；当前无需训练期实时渲染、远端姿态流或同时显示全部训练环境。

## 6. CPU 首版的具体离散与范围

实现入口为 `include/duck/solver.hpp`、`src/solver.cpp`；C++ 核心无外部物理库依赖。`scripts/model_io.py` 使用 MuJoCo **离线编译**模型，再导出质量、惯性、位姿、关节和碰撞常量到 `DUCK_MODEL 1` 文本格式。时间推进完全由 C++ 执行。当前为 FP64；原生 `Batch` 提供顺序执行参考，Python `CpuBatch` 按环境分配 CPU 线程；两者独立存储并支持逐环境重置。

- 刚体位姿以质心/主惯性轴为参考，四元数采用 `wxyz`，线速度和角速度均在世界系。平移预测为 $x_p=x+h v+h^2g$。角速度先显式处理力矩与陀螺项，再用 SO(3) 指数映射预测旋转。
- 旋转惯性项为 $\tfrac{1}{2h^2}\theta^T I_{world,0}\theta$，其中 $\theta=\log(q q_p^{-1})$；世界惯性冻结于步初，使用 log Jacobian 线性化。局部系统采用惯性、Gauss–Newton 项和几何刚度列范数的正对角近似，Cholesky 求解；旋转/平移增量分别限制为 0.25 rad/0.1 m。
- 每轮顺序更新刚体块，再更新乘子。等式用 $C-\alpha C_0$；单边约束只稳定步初已有违反量，乘子截断到允许范围。跨步乘子乘 $\alpha\gamma$，惩罚系数乘 $\gamma$ 后夹取下限；未饱和约束按 $k\leftarrow k+\beta|C|$ 增长。
- 当前默认 $h=0.001$ s、$\alpha=0.9$、$\gamma=0.99$；线性/角约束的初始惩罚为 1000/1，上限为 $10^9/10^7$，增长系数为 $10^7/10^5$。验证脚本每步最多 200 轮；局部更新和稳定化约束误差都小于 $10^{-7}$ 时停止，耗尽预算另行计数。不同单位的误差仍分别输出，停止条件并非完整 KKT 证书。
- hinge 约束包含三个锚点条件、两个轴向正交条件；限位使用关节角上下界。关节粘性阻尼与 armature 采用隐式相对角增量项；干摩擦使用有界乘子。恒定力矩/有界 PD 作用于相邻刚体且满足作用反作用；真实执行器扩展尚未验证。
- 碰撞仅支持 **z=0 平面**与球、盒、胶囊、网格接触。网格使用实际顶点，不用外观包围盒代替；每个几何体保留最多四个分散接触点。法向乘子非正，切向力投影到库仑圆锥；静摩擦锚点和乘子按几何/特征标识缓存。当前候选距离为 3 mm，点间距为 5 mm，需要后续随场景尺度验证。

本实现沿用 AVBD 的增广约束、惩罚增长、稳定化及 warm-start 调度，采用独立 SO(3) 离散与预测；**不是论文刚体离散的逐式复现，也不声称已经验证任意时间步稳定性**。参考实现锁定为 [7701bd4](https://github.com/savant117/avbd-demo3d/tree/7701bd427d55ca5d03ea1fdf331912ded9169f4b)，相关版权说明保留在源文件。

整机对照保留原始质量、惯性、关节、阻尼、armature 和干摩擦，移除执行器以测试被动释放，并关闭双方的自碰撞。默认参考将 MuJoCo 接触、限位、干摩擦的 `solref` 设为 `0.002 1`、接触 `solimp` 为 `.99 .99 .001`，近似自研硬约束；`--original-softness` 保留上游软约束供诊断。两种对照不可混作同一配置。

阶段 1 CPU 参考不包含 FP32/CUDA；新增共享核心见下节。当前不支持通用刚体间碰撞、复杂地形、任意 MJCF 语义、连续碰撞检测。导入器对已知不支持的关节、固定子连杆、执行器、显式接触对、tendon/equality、流体、flex/plugin、非零碰撞 margin/gap 等配置报错。精度与吞吐结论仅覆盖开发路径中列出的场景。

## 8. CPU 训练与回放的具体接口

`src/bindings.cpp` 的 `_duck_cpu.CpuBatch` 接收离线模型、`num_envs`、物理时间步、迭代预算和 CPU 工作线程数。各环境拥有独立状态，线程按环境分配，单个环境内部仍顺序更新刚体。步进时释放 Python GIL；同一实例的并发调用显式拒绝。返回数组拥有自己的内存，不暴露会在下一步失效的 C++ 指针。

| 接口 | 数据约定 |
| --- | --- |
| `reset(ids, angles, roots)` | 指定环境的关节角 `[N,14]`；基座质心平移和世界系旋转向量增量 `[N,6]`。按拓扑顺序重建连杆，清空速度、乘子和接触缓存。 |
| `step(targets, substeps, kp, torque_limit, forces)` | 关节目标角 `[E,14]`；基座质心世界系外力 `[E,3]`，单位 N，持续整个控制周期。其他量为 SI。 |
| `body_state()` | FP64 `[E,16,13]`：世界系质心位置、主惯性轴 `wxyz` 四元数、世界系线速度和角速度；索引 0 为固定世界。 |
| `joint_state()` | FP64 `[E,14,2]`：关节角 rad、沿 hinge 轴投影的相对角速度 rad/s，顺序由 `joint_names` 返回。 |
| `diagnostics()` | `[E,5]`：控制周期内最大的锚点误差、穿透、接触数、所有子步是否收敛、最大轴向误差。 |

外力使平移预测变为 $x_p=x+h v+h^2(g+f/m)$，不改变惯性和关节定义。碰撞几何预计算刚体系顶点，并使用保守包围球排除远离地面的几何；实际接触仍使用原网格顶点。

`python/duck_gym/env.py` 对接 **rsl-rl-lib 2.3.3**，策略使用 PyTorch CPU FP32，求解器保持 FP64。每个控制周期 20 ms，包括 20 个 1 ms 子步，每子步最多 200 轮。14 维动作裁剪到 `[-1,1]` 后，作为上游名义站姿的目标角偏移，再裁剪到模型关节限位。动作比例属于训练配置，保存在运行的 `config.json`；不改变机器人参数。电机使用原 XML 的 `kp=0.55`、力矩上限 `0.96 Nm`，保留关节 damping、armature、frictionloss；尚未实现 BAM/齿隙模型。

名义姿态取资产所固定上游提交的 `microduck_constants.py: HOME_FRAME`（STAND2）。初始高度由碰撞网格最低点计算，留 0.1 mm 间隙。训练时关节角和基座横滚/俯仰分别在 ±0.01 rad 内初始化，基座另抬高 1 mm。这些是仿真初始化条件，不是实机参数辨识结果。

52 维观测依次为基座坐标系的重力方向、线速度、角速度、质心高度相对名义值、14 个关节角偏差、14 个关节速度乘 0.1、14 个上一周期动作。奖励按控制时间步缩放，鼓励直立、保持高度和低速度，惩罚角速度、关节偏差、动作幅度与变化；具体权重集中在环境代码。倒地和超时分别处理，`time_outs` 为 rsl-rl 提供超时 bootstrap 掩码。完成的环境单独重置，返回重置后的观测，同时在 info 中保留终止观测和环境索引。

`train_standing.py` 使用真实 PPO 更新，保存权重、优化器、观测归一化统计、随机种子、参数变化量及源码/模型哈希。新策略的末层初始化为零，从名义 PD 姿态开始学习残差；高斯探索仍启用。评估必须恢复同一动作尺度与归一化统计，关闭自动重置，不能将中途重置拼接为连续站立。

`python/duck_gym/render.py` 将每个刚体的质心/主惯性轴位姿转换为 link 和 geom 世界位姿；不会通过关节 FK 投影回理想机构，从而保留自研约束残差。`render_trajectory.py` 读取本地轨迹，加载全部原始网格和材质，生成 MP4 与预览图；MuJoCo 仅在初始化时计算静态渲染数据，回放不调用 `mj_step`。离线回放不依赖训练是否开启显示器。

## 9. CUDA 与共享 CPU 核心

源码组织采用 `.cu` CUDA 入口、`.cpp` CPU 入口及 `.cuh` 共享实现头文件：`extension.cu` 和 `cpu_bindings.cpp` 均包含 `kernel.cuh`，后者包含 `convex.cuh`。两个共享头在不同标量命名空间中各展开一次，因此有意不使用 include guard；文件格式迁移保留原有求解方程。

`src/cuda/kernel.cuh` 以 FP32/FP64 分别实例化，在 GPU 与 Mac CPU 使用相同数学和双色迭代顺序；`src/solver.cpp` 保留为独立 FP64 参考。CUDA 每个环境一个 32 线程块，关节树按二分图着色，同色刚体块并行，颜色之间同步；关节/接触乘子并行更新。当前仅支持地面接触，因此没有跨颜色之外的刚体接触耦合。每环境容量为 32 个刚体（含 world）、32 个 hinge、32 个碰撞几何和 128 个地面接触；超容量与不支持的拓扑在加载时拒绝。

共享核心把有界 PD 电机纳入局部能量导数：令关节角为 $q$，目标为 $q_d$，外加关节力矩为 $\tau_0$，使用 $f=\operatorname{clip}(k_p\operatorname{wrap}(q-q_d)-\tau_0,-\tau_{max},\tau_{max})$，梯度贡献为 $J_q^T f$；未饱和时增加 $k_p J_q^T J_q$，饱和时该刚度为零。电机与 armature、阻尼在同一隐式求解中处理，旋转预测仅保留陀螺项。原 CPU 参考仍采用显式电机预测；因此受控系统对照须区分离散方法差异。该改动不改变源模型的增益、惯量或力矩上限，长期效果需以阶段验证结果为准。

CUDA `CudaBatch.reset(mask,q,root)` 接收同设备连续 Tensor：布尔掩码 `[E]`、关节角 `[E,J]`、根位姿增量 `[E,6]`；`step(target,forces,substeps,kp,limit)` 接收目标 `[E,J]` 和基座世界系外力 `[E,3]`。`state()` 返回独立拥有内存的刚体 `[E,B,13]`、关节 `[E,J,2]`、诊断 `[E,6]`；刚体字段为 COM xyz、wxyz、世界线速度与角速度，诊断依次为锚点误差、穿透、接触数、所有子步收敛、轴误差、数值失败标志。输入必须匹配构造时的 FP32/FP64；数值失败按环境标记，显式重置后清除。持久状态由 CUDA event 串行化跨 stream 调用，输入通过 `record_stream` 延长分配器生命周期，输出不暴露内部状态别名。

`TensorEnv` 在 CUDA 上完成观测、奖励、终止与掩码重置；仅日志/PPO 统计允许必要标量同步，训练不将完整仿真状态传回 CPU。站立观测 52 维；移动观测添加世界系二维速度命令、朝向 cos/sin、周期相位 sin/cos，共 58 维。动作是 14 个关节的限幅残差目标；相位仅作为策略输入，不推进机器人位姿。奖励包含直立、高度、命令速度跟踪、角速度、朝向与动作平滑。超时通过 `time_outs` 与物理失败区分。

本地推理使用 `_duck_reference` 的共享 CPU 核心，保留训练精度、时间步、动作尺度、权重和归一化统计。离线轨迹记录全连杆位姿与实际外力；`render_trajectory.py --follow` 跟随基座移动并保留完整资产外观。MuJoCo 仅编译资产与渲染，不推进训练或推理动力学。

移动训练可启用 `--gait`：`prepare_gait.py` 离线用原始资产的脚部运动学生成四方向周期关节参考，记录 IK 残差与参考参数。运行时在 GPU 查表插值，策略输出其关节残差；参考不会修改刚体位姿、速度、重力或外力。参考的步长/抬脚/重心摆动属于训练辅助参数，不是新增机器人参数。采用参考时速度奖励更窄，以降低原地站立的局部最优；策略是否真正移动仍只由阶段 7 的独立物理轨迹验收决定。参考表随 checkpoint 的模型配置一起保存，本地推理使用同一份数据。

`--foot-clearance` 使用原始足底碰撞网格所有顶点在世界 z 方向的最小投影，按左右脚相位惩罚实际最低点与抬脚目标的高度差。该量在 GPU 计算，不能仅由脚部中心升高或脚底滚动获得离地奖励。参考高度来自当前步态设置；评估仍使用真实速度、朝向及连续时间判据，不把抬脚奖励当作移动通过。

`contact_forces()` 返回 `[E,B,3]` 的世界系地面合力（N），由接触乘子按刚体汇总，返回独立快照；不包含内部关节力。CPU 静止盒测试检查法向合力等于重量，CUDA 边界与 sanitizer 检查生命周期和写入范围。`--load-transfer` 用该力相对机器人重量的比例，按左右脚相位引导卸载；奖励裁剪极端载荷，不修改物理接触力。`--tracking-sigma` 显式设置速度奖励宽度，保存在训练配置中，用于对比起步信号强弱。

`--tracking-weight` 与 `--heading-weight` 分别设置速度和保持初始朝向的奖励系数，默认 4 和 0.4；它们属于学习超参数，所有覆盖值写入新训练配置。TensorBoard 同时记录实际命令方向速度、速度误差、偏航及物理失败比例，避免只观察总奖励。恢复训练默认继承步态开关、参考表、精度、步长、子步数和求解迭代预算；显式参数才覆盖原值。评估平均速度由真实基座位移除以时间得到，短于要求时长的诊断不能获得完整验收通过。

`--command-direction` 默认为 `all`，每个 env 重置时抽取四方向之一；也可固定一个方向进行专项训练，状态和动作接口保持一致。固定方向随配置保存和恢复，评估默认选择该方向。专项 checkpoint 的结果只能代表已测方向，不代表联合策略或运行中切换方向的能力。推理轨迹保存实际关节目标、关节状态、全连杆位姿、地面合力及外力，便于区分动作限幅、接触变化与跌倒原因。

启用 `--velocity-filter-seconds` 时，速度跟踪使用世界系水平速度的一阶低通状态，$\bar v_{t+1}=(1-a)\bar v_t+a v_{t+1}$，$a=1-\exp(-\Delta t/\tau)$。该状态加入观测，移动观测由 58 维变为 60 维，并随单环境重置清零。其目的为减少对步态内侧摆的惩罚；最终验收始终读取原始物理轨迹，过滤后的奖励不能替代实际速度指标。旧 checkpoint 追加输入时，新增首层权重和 Adam 动量初始化为零，保留旧权重、优化器与归一化统计，适配文件单独保存；测试验证扩维前后旧策略输出一致且优化器可继续更新。

移动评估协议集中在 `configs/locomotion_evaluation.json`，当前 `status=proposed_unconfirmed`。`passed` 仅表示数值自检通过，`accepted` 还要求协议已获用户确认。平均速度来自实际基座首末位移；窗口误差检查所有完整滑动窗口，失败轨迹截断在第一次失败时刻，不能把重置或短时片段拼接为连续运行。

评估默认每次只向策略网络输入一个 env 的观测，以减少 GEMM 批大小造成的浮点分支差异；`--batch-policy` 显式启用整批推理，报告分别记录物理 env 数量与策略批大小。这不保证 CPU/CUDA 逐位相同，最终仍须分别验证。拥有独立内存的轨迹快照先缓存在其设备，结束后集中转移；CUDA 每个模拟秒检查一次全部失败，具体失败时间仍逐控制周期记录。报告保存源码、模型、原生扩展哈希与运行配置。

每次训练在自己的输出目录 `prepared/` 离线生成模型，避免并发训练相互覆盖。推理所需原生模型、元数据和参考表复制到该次训练的 `model/`，配置保存各文件哈希，评估默认校验。可视化另用本地完整资产；回放记录轨迹/可视模型哈希、相机参数、网格/材质数量和零物理步进，支持跟随视角及命令速度标注。

## 10. 步态方法审查与空翻实验（2026-09-11）

PPO、并行环境、关节目标角和状态反馈是常见的腿式机器人 RL 组合；选择这些组件不能说明具体奖励和策略已合理。对照 [legged_gym 的实际奖励实现](https://github.com/leggedrobotics/legged_gym/blob/master/legged_gym/envs/base/legged_robot.py) 及与本项目资产相同版本的 [MicroDuck 速度任务](https://github.com/pollen-robotics/microduck_rl/blob/1e79c29c97d8b38aee9eefde77a545860ba7658e/src/mjlab_microduck/tasks/microduck_velocity_env_cfg.py)，原方案有以下缺口：

- 移动分支覆盖站立奖励时丢失实际关节姿态约束，头颈成为没有姿态目标的自由控制通道；动作幅度惩罚无法替代实际姿态误差。
- 只要求速度和基座稳定，没有独立量化完整足底离地、支撑接触点滑动及步态样式。足底高度/载荷辅助奖励不足以禁止拖脚；先前人工 IK 表只验证运动学残差，没有证明动力学可行。
- 逐方向选 checkpoint 只说明特定初态的特定轨迹，不能证明统一策略、随机初态、命令切换或 sim2real。官方还包含 BAM 执行器、域随机化与自碰撞处理，本引擎尚未等价实现。

修正采用关节目标 PPO 加显式运动质量项；`MotionEnv` 与旧环境分开，保留旧案例可追溯性。`prepare_motion.py` 从原始碰撞顶点导出支撑凸包，仅作为传感器；线性方向投影的极值不变，不替换求解器碰撞资产。最低支撑带的点速度按 $v_p=v_{COM}+\omega\times r$ 计算。训练提供头部/腿部姿态、速度、支撑滑动、交替摆腿/卸载与动作平滑项，具体超参数属于实验设置，不能冒称官方原配方或验收容差。所有奖励状态须随 env 重置，并进入观测以保留状态信息。

空翻有 [DeepMimic 的参考动作模仿路线](https://xbpeng.github.io/projects/DeepMimic/index.html) 和 [WASABI 在 Solo 8 上的后空翻实验](https://proceedings.mlr.press/v205/li23b.html) 等先例；它们支持采用运动参考/轨迹优化与 RL 的方法方向，不证明 MicroDuck 的执行器及形态足以空翻。官方 MicroDuck 的 [roulade 任务](https://github.com/pollen-robotics/microduck_rl/blob/1e79c29c97d8b38aee9eefde77a545860ba7658e/src/mjlab_microduck/tasks/microduck_roulade_env_cfg.py) 是头部接触地面的滚翻，不可冒充空翻。

本项目空翻探索在原生物理内搜索关节目标序列，或先学习起跳落稳，再引入空中旋转。搜索结果只作为候选，未经动力学验证不作为模仿真值。动作只施加模型允许的关节力矩，不直接写入位姿、速度或给予外力。旋转用相邻四元数的增量在世界 y 轴的投影累计，避免 Euler pitch 的 ±90° 折返；只统计同一段连续腾空，不能把多次跳跃旋转相加。

`aerial_detector_version=2` 要求整个控制周期的**所有物理子步均无接触候选**、末子步地面合力为零、所有原始碰撞几何最低点高于地面。接触候选包含近接触带，所以这是保守判定；末子步力单独为零可能只是接触抖动。`audit_aerial.py` 从保存的轨迹重算连续腾空段，排除初始帧，分别报告旋转、落地、非足部触地和初始/外部动量。接触合力目前只记录末子步，不能据此排除落地周期内短暂的非足部触地；最终空翻验证还需要更完整的接触记录和自碰撞。旧版本报告不能自动升级成严格判据通过。 `aerial_detector_version=3` 进一步要求首次完整无接触区间开始时质心竖直速度为正；失去支撑后收腿下坠的无接触片段不获得起跳/空中动作奖励。严格腾空、向上起跳与可靠落地是三个不同条件。

官方头部控制允许周期摆动，额外惩罚约 1 秒低通后的持续姿态偏置；本实验的 `walking_bias_recipe` 借鉴这一结构，具体权重不宣称等同上游。支撑点平均速度可能被旋转脚掌两侧的相反滑动抵消，独立审查因此同时计算最低支撑带内各点速度的 RMS；训练中的均值滑动项不能代替该审查。

`prepare_crouch.py` 通过双脚位置/朝向与质心水平投影约束生成蹲伸 IK；`prepare_feedforward.py` 和 `prepare_aerial_reference.py` 只补偿原模型的关节阻尼、armature 和平滑干摩擦，并换算为 PD 目标偏移。它们**不是完整逆动力学**，没有证明浮动基座平衡或接触力可行性；补偿请求没有超过力矩上限也不等于整段动作能执行。早期相同模型和目标的跨引擎控制诊断已归档，未证明这些参考可执行。

`train_motion.py --resume` 只允许相同任务、奖励及控制语义。`--warm-start-walking` 则明确是迁移：核对原模型/参考哈希并保留参考、动作尺度和求解预算，只移植 actor 与观测归一化，追加输入初始权重为零，critic 与优化器重新初始化。新速度滤波由整控制周期位移计算，旧策略使用末子步速度，因此仍需重新验证；不能把迁移当作无变化地恢复旧技能。`jump_training.json` 的起跳速度/质心上升项只用于探索，真实腾空与落稳仍由独立轨迹判定。

## 11. 纯引擎 GPU 基准

`scripts/benchmark_engines.py` 比较原生 AVBD 与 mjwarp，使用 `requirements-benchmark.txt` 和 `scripts/remote/provision_benchmark.sh` 建立独立依赖环境。仍须经 `scripts/remote/run.py` 同步、校验、构建和持久运行。每个后端/环境数使用独立子进程；同一次运行共享各自的编译缓存，第一组创建新的原生构建目录与 Warp 缓存目录。依赖安装和等待空闲 GPU 不计入引擎初始化。

`--envs` 指定批量规模，`--steps` 为每轮物理步数，`--chunk-steps` 为每次原生调用/Graph 重放包含的物理步数。mjwarp 使用官方推荐的 [CUDA Graph 捕获](https://mujoco.readthedocs.io/en/latest/mjwarp/index.html#graph-capture)，保留显式非默认 PyTorch/Warp stream 的生命周期，CUDA Event 与引擎执行共用该 stream。每轮先在计时外重置相同状态；吞吐为 `num_envs × steps / median(gpu_seconds)`。不包含策略、奖励、渲染或计时内主机回传。

`--warmup-steps` 与 `--warmup-seconds` 是同时满足的预热门限：后者累计 CUDA Event 测得的 GPU 时间，不能用首次编译或 CPU 等待凑时长。报告同时保存预热的实际步数、GPU 时间与墙钟时间。初始化由导入、CUDA context、资产准备、引擎编译/加载、设备分配、首次执行和 Graph 捕获各阶段组成；`ready_for_measurement_total_seconds` 另包含独立预热。冷编译与后续缓存命中必须分别解释。

每组开始和每轮结束检查选定 GPU 的其他计算进程；`--wait-for-gpu-seconds` 可在开始前等待空闲，不暂停他人的任务。正式报告保留逐轮计时、同步墙钟、硬件状态和有效性检查。诊断不在计时区间：AVBD 误差最大值覆盖最后一次调用的子步，mjwarp 接触距离来自最后物理步的 forward 阶段；这不是整段轨迹的全步误差证明。两种坐标表示、接触生成、PD 离散和迭代方法不同，同为 FP32 或同样的迭代上限不构成等精度证明；具体实测设置和数据只在开发路径维护。

Newton 适配器为 `scripts/benchmark_newton.py`，通过 `--engines newton mjwarp` 比较完整 `SolverMuJoCo.step` 与直接 mjwarp。根据 [Newton 官方接口](https://newton-physics.github.io/newton/latest/solvers/mujoco.html)，此后端包含 Newton 控制/状态推送、MuJoCo Warp 物理步进与 Newton 输出状态转换，不能表述为另一套独立物理求解算法。使用默认每步状态同步（`update_data_interval=1`）、MuJoCo 接触、关闭 sleeping，并以偶数子步的双缓冲 CUDA Graph 捕获整个调用路径。显式设置 `mesh_maxhullvert=-1` 和零默认 gap，使碰撞凸包不受 Newton 默认 64 顶点限制；多点接触开关从参考模型读取。导入检查另比较有效碰撞掩码、接触参数和网格在固定采样方向上的支撑距离。

`requirements-benchmark-newton.txt` 锁定 Newton 及其支持的 MuJoCo 版本；安装命令为 `bash scripts/remote/provision_benchmark.sh <workspace> benchmark-newton`，解释器为 `<workspace>/venv-benchmark-newton/bin/python`，与训练和原 mjwarp 基准环境隔离。各引擎有独立的新 Warp 缓存，避免先跑的一方替另一方完成冷编译。资产经 `ModelBuilder.add_mjcf` 导入后复制多个 world；保留视觉几何、原惯性、关节与电机参数、碰撞掩码和多点接触选项。地面与机器人同次导入时不能设置 `enable_self_collisions=False`，因为它会屏蔽该次导入的全部形状对；原 MJCF 掩码本身已禁用机器人自碰撞。导入检查比较质量、物理参数、世界系 COM 与惯性张量，避免把坐标系旋转导致的主惯性轴重排误判为质量属性变化。

### 刚体 AVBD 对照

`--engines avbd newton-avbd --physics-profile avbd-common` 用自研最大坐标 AVBD 对照 Newton `SolverVBD` 的刚体路径，显式选择 `rigid_compliant_alm=False`；不能用 `SolverMuJoCo` 或自研约化坐标候选代替。共同模型的选择与运行进度见开发路径。原始资产只读，两端导出时同时移除不支持的关节 armature、干摩擦和电机力矩上限，保留 HOME PD 与粘性阻尼。Newton 端须显式建立刚体着色、匹配 HOME 的结构参考姿态、控制映射和碰撞流水线，每物理步均执行碰撞与求解；重置同时清除两个状态和求解/碰撞历史。有效地面摩擦系数须对齐，不能只比较两套引擎的输入材料系数。

正式计时前逐物理步检查完整轨迹并记录关节、接触和姿态诊断；另记录普通步进重复、普通步进与 chunk/Graph、以及热身后每次测量的末态差。两端重置后的物理初态必须逐字节相同，非有限状态与容量溢出继续阻止出具有效结果。自研路径保留严格重放检查；Newton 默认并行原子累加不保证确定性，可显式使用 `--newton-avbd-replay-policy report` 将未通过的重复性检查如实保留在报告中，不将它重新标成通过，也不通过增大数值容差掩盖差异。该模式仍检查逐步直接轨迹、每个 Graph chunk 及正式轮末的有效性，不能证明每次计时轨迹的所有中间步都无异常。性能主对照使用默认非确定性模式；`--newton-avbd-deterministic` 同时启用接触排序与求解器 `RUN_TO_RUN`，只作另列的诊断，不能把额外确定性成本混入默认吞吐。上述执行检查不作为不同 AVBD 实现的物理精度验收。两种实现的旋转离散、摩擦和接触流形不同；同为 50 轮预算也不代表相同约束误差，报告同时保留吞吐与质量，不能直接声称等精度。

Newton 的接触历史通过 `--newton-avbd-contact-history` 另列控制组：使用 `latest` 匹配和乘子/惩罚热启动，保留固定迭代数；该模式自动启用接触排序，但不强制确定性原子归约。纯 HOME PD 工况不提交额外广义关节力，避免全零 `joint_f` 的复制与映射。`--newton-avbd-verify-buffers` 才将官方可选缓冲诊断 kernel 加入计时；默认在计时外读取候选对、mesh-plane、接触归约哈希、最终接触和匹配缓冲计数。未暴露的计数明确标注，饱和且无法确定是否丢点的缓冲不能被认证为完整检测。

## 12. 跨引擎动力学对照

`scripts/compare_avbd_long.py` 单独比较自研 AVBD 与 Newton 刚体 `SolverVBD` 的连续共同模型轨迹。采用固定 HOME 目标，每个物理步保存全部动态刚体，正式轨迹中不重置；图捕获预检和预热之后重新建立初态。Newton 以刚体名称/环境号建立双射，把 link 原点转换为世界 COM，姿态右乘资产固定 `body_iquat` 到主惯性系；其世界 COM 线速度和世界角速度直接对应 native。此路径不拟合初始姿态差，也不逐帧配准。Graph 内逐步复制状态，预检最后记录帧须与当前状态完全相同；逐步检查有限状态和已暴露的容量计数。该记录流程的耗时不用于吞吐，允许共享 GPU 时必须显式启用并记录。

`scripts/analyze_avbd_long.py` 在 CPU 上独立读取两端轨迹。位置相对差定义为 `||p_native-p_newton||₂ / ||p_newton||₂`，高度为 `|z_native-z_newton| / |z_newton|`；Newton 是对照实现，不是物理真值。零分母明确未定义，不添加 epsilon；同时报告绝对差、分母、最大事件的时刻/环境/刚体及原始数值。位置百分比依赖世界原点，高度百分比受近零高度影响。另列根部/全身统计、逐帧全身 L2 归一化、姿态最短旋转角和速度绝对差；不同指标各自搜索最大值，不拼接不同事件的分子分母。样本必须有完全相同的时间轴，不插值；累计最大值与末帧误差分开。这些统计不自动构成物理精度验收。

早期 AVBD/mjwarp/`SolverMuJoCo` 的一次性动力学实验已归档；历史结果见开发路径，不作为当前刚体 AVBD 对照入口。

## 13. 官方步态任务对齐

上游代码与依赖以 `configs/official_baseline.json` 固定，不以开发分支的后来修改替代。当前对齐目标使用 BAM 电压控制 XL330/m6，并非早期 XML 固定 PD 模型。固件先由位置误差产生 PWM，占空比先受电流窗口限制，再受电池电压限制；力矩包含反电动势。每个物理步都重算干摩擦预算和黏性阻尼，不能在控制周期内保持一次 PD 计算。

`python/duck_gym/actuator.py` 接收固定版本的模型参数，向 CPU/CUDA 通用 `step_motor` 输出 `[num_envs, num_joints, 3]`（Nm、Nm、Nm·s/rad），只推进一个物理步；输入已包含执行器限幅。调用者维护电池压降使用的上一步原始电机力矩，以及摩擦使用的上一步实际广义执行器力。外部负载按官方定义为 `-qfrc_bias + qfrc_constraint - qfrc_friction`。原生 `generalized_loads(root_offset)` 用 RNEA 在当前关节状态、广义加速度为零时计算重力/科氏偏置，并将已求解的接触和限位力沿关节投影；不包含干摩擦项。`root_offset` 为根连杆原点到质心、在主惯性坐标系表达的偏移。输出 `[E,J,3]` 分别为偏置、接触/限位负载、实际执行器力矩，不调用 MuJoCo 推进或计算这些力。当前姿态的 RNEA 与上游上一次 forward 的力评估时刻仍有离散差异。`scripts/validate_bam.py` 直接对照固定 BAM 的电机和 `BamActuator._compute_friction_budget` 方程；这不验证负载估计、整机或步态。

固定提交中 BAM 的 NumPy `Model.compute_frictions` 和 mjlab 的 m6 二次项存在符号/等幅分支差异；对齐对象是实际用于官方训练的 mjlab 分支，不能将另一个接口当作同一方程。原始源代码及 Apache-2.0 许可保留在固定版本包。

干摩擦收敛增加投影残差 `|λ − clamp(λ + ρ Δθ, −f, f)| / ρ`，与约束误差一起判断；小的刚体更新量不能单独证明静摩擦已经停止滑动。`step` 仍是原 PD 接口，并恢复模型的固定力矩、阻尼与摩擦参数，避免之前 `step_motor` 的动态参数泄漏到后续 PD 调用。


`BamEnv` 的 actor 保持官方 61 维顺序：根局部角速度、单位重力方向、相对关节角、延迟一控制步的关节速度、上次动作、速度命令、零头部/身体命令。critic 为 76 维，另含真实根局部线速度、当前关节速度、足部地形高度/腾空时间/接触、世界系足部合力的 `sign(F) log(1+|F|)`；初始版本用于名义平地，因此射线地形高度简化为足部 site 的世界 z。刚体质心速度先转换到根连杆原点，角动量同时包含自旋与相对整机质心的轨道部分。

`WalkingReward` 将实际动力学特征与奖励方程分离，头部 EMA、摆脚峰值、接触/腾空计时均按 env 重置；默认保留上游速度核及课程。低速实验显式配置更窄的速度核，其他上游方程不变，不能称为未修改官方任务。观测/执行器延迟、接触发生时刻、有限迭代约束、地面版模型缺失的自碰撞与域随机化仍是迁移差异；新增双体接触见第 14 节。足底完整凸包最低点只用于独立评估，不参与位姿更新，也不以视频运动学重建替代原生物理。


平均速度实验保留原 15 项瞬时奖励，另维护世界系线速度指数平均，物理子步系数为 `1-exp(-dt/tau)`；其局部坐标状态作为 critic 的额外 3 维，按环境重置，actor 输入维数保持不变。额外奖励仅衡量平均水平速度命令误差，避免将正常换脚摆动误当成方向跟踪失败。保持初始朝向时，命令发生器输出 `clip(0.5*wrap(target_yaw-yaw), -1, 1)`，策略仍通过原有电机目标驱动机器人，不直接修正位姿。参数与启用状态保存在该实验配置和导出策略元数据；默认名义迁移接口不启用这些变化。


可选 `VelocityCommandServo` 是策略之外的命令反馈：世界系水平速度经过 EMA，PI 根据目标与平均速度误差产生世界系需求，再转到机器人水平朝向坐标系，按上游速度范围限幅并回算积分饱和；朝向使用包裹角度误差的 P/D 控制。它只改变 actor 的命令输入，真实运动仍由 BAM 和原生物理产生。控制增益属于显式实验配置，不是已识别的机器人参数。评估分别保存用户目标 `target_series` 和实际策略输入 `command_series`，视频标明该组合，不能将反馈控制结果冒充裸策略成绩。

朝向奖励实验在平均速度配置上增加 `exp(-wrap(target_yaw-yaw)^2/variance)`；朝向误差进入 critic，按 env 重置目标，actor 接口不变。该项衡量累计朝向偏差，原角速度跟踪项仍保留。具体权重、方差和来源模型由实验配置与运行归档记录；默认上游奖励对照不启用它。


命令反馈可选限制世界系目标水平速度的变化率，按向量范数截断每个控制周期的变化；积分器使用平滑后的目标，重置时清除该状态。用户目标和实际策略输入继续分别保存，完整启动轨迹不因测量预热而从碰撞审查删除。

离线支撑滑动诊断计算碰撞顶点最低点以上 0.5 mm 支撑带内逐点 `v_COM + omega cross r` 的水平 RMS，避免左右速度抵消；这是几何代理值，没有接触压力加权，也不把足部 site 速度等同于真实接触点滑动。头部同时报告均值之外的最大值/分位数，避免周期摆动被均值掩盖。



## 14. 双刚体凸接触（实验实现）

`src/cuda/convex.cuh` 从 [libccd v2.1 的 MPR](https://github.com/danfis/libccd/tree/v2.1) 门户发现/细化算法改写，保留 BSD-3-Clause 署名和许可；使用固定容量、显式迭代上限及 CPU/CUDA 共用标量数学。球/胶囊采用解析支持映射，盒/网格采用顶点支持映射；CUDA 同一 warp 的线程共同搜索支持点。返回分离、接触或数值失败，失败使对应 env 终止，不能当作无碰撞。MPR 分离深度不保证等同于最小平移深度。

`DUCK_MODEL 2` 在每条 shape 记录的顶点后增加是否参与地面碰撞的布尔位；末尾为碰撞对数量及 `(shape_a, shape_b, sliding_friction)`。导出遵循原碰撞位标记和父子过滤，显式排除/特殊接触维数仍拒绝导出。格式 1 保持地面接触语义；独立的旧 `duck::Solver`/`_duck_cpu` 对含双体接触的模型明确报错，完整 CPU 求解使用共享 `CpuBatch32/64`。

每对凸体当前生成一个接触点和冻结于该物理步的法向。近接触带为 3 mm 加一物理步线速度/角速度的运动界，支持映射作对称膨胀；由膨胀深度还原有符号间隙。碰撞双方的局部接触点及切向基用于

\[
 C_k=e_k^T(x_A+R_A r_A-x_B-R_B r_B),\quad
 J_A=[e_k^T,(R_A r_A\times e_k)^T],\quad
 J_B=[-e_k^T,-(R_B r_B\times e_k)^T].
\]

沿用 AVBD 的法向互补投影、库仑滑动摩擦与惩罚更新。力和力矩同时作用于双方，接触/限位广义负载沿关节投影；新增接触若连接同色动态刚体，为其中一体分配新的独立颜色以防 CUDA 并发冲突。近邻接触可投影复用旧乘子；不保证完整接触流形、滚动/扭转摩擦或连续碰撞检测。有限迭代和冻结接触几何仍可能产生穿透，须用独立窄相和步长细化复查，不能把“加入响应”当成“接触精度已验收”。

`contact_forces(ground_only=True)` 只报告地面合力，足部自身碰撞不会被误判为支撑；默认返回全部接触合力。`self_contact_stats()` 返回每 env 的活动自身碰撞对数和当前接触约束穿透。`BamEnv` 在控制周期内对全部物理子步取最大值，供奖励、失效检查与记录使用；这不同于轨迹中末子步的刚体快照，离线 MuJoCo 审查仍独立计算真实网格穿透。

`train_bam_native.py --resume-native` 恢复 actor、critic、优化器和内嵌归一化，并恢复环境课程计数，从已完成 checkpoint 的下一轮继续；模拟环境重置，不保存旧 rollout。实验奖励权重覆盖显式保存在配置中，不能将改动后的任务称作未修改官方配方。

独立评估可用 `--record-physics` 保存每个物理子步的刚体、关节和支撑状态，`audit_bam_contacts.py --physics` 按这些最大坐标姿态逐步调用 MuJoCo 窄相，不推进参考物理；报告与常规控制帧审查分开保存。完整官方 BAM 模型回放使用约 145° 侧前方镜头，避免把背面的白色头壳当作正面。

## 15. 头部稳定与阶段技能接口

行走实验可增加瞬时头部代价 `-w_q sum((q_head-q_home)^2) - w_v sum(dq_head^2)`。该项独立于原约 1 秒 EMA 偏置项，防止正负摆动相消。另一种明确的动作接口是 `neutral_head`：头颈目标通过原 BAM 执行器保持 HOME，所有头颈刚体、关节、惯性、负载与有限力矩仍参加物理求解，不将关节固定在空间中。训练观测中的 previous action 使用实际应用的目标偏移，部署包装器保存相同映射；对照时必须区分奖励微调与中立头部接口。

`BamSkillEnv` 在原 61 维 actor 观测后追加归一化阶段、阶段正弦和 14 维关节参考，共 77 维。critic 另有质心速度、身体高度、腾空/落地状态与旋转累计量等，当前为 101 维。动作是参考姿态上的有界残差 `q_target = q_home + q_reference(phase) + scale*tanh(action)`；参考来自固定足姿/质心投影 IK 或独立验证的动力学轨迹，只提供目标，不修改身体状态。阶段、奖励和残差幅度属于实验配置，不是机器人参数或用户验收标准。

下蹲、起跳、落地采用独立阶段奖励。起跳奖励向上质心速度与有效离地，飞行时不施加地面高度/双足支撑要求；空翻阶段不沿用走路的 70° 倾斜终止。所有当前技能回合仍从原始静止初态开始，尚未实现参考状态初始化。内部翻转使用逐步四元数旋转增量累计，不能用周期性的 Euler pitch 是否回到零来证明一周旋转。

`contact_counts()` 返回每个物理步的 `[ground_candidates, self_candidates]`，与活动接触力分开。候选生成有 3 mm 近接触带，不能把仍有候选等同于仍在承重。当前 BAM 技能逐物理步要求两足实际地面力低于既有接触检测阈值（每足 1e-5 N）、完整足底间隙大于 1e-5 m，且首次离地时质心向上；内部接触本身不意味着受到地面支撑。该间隙是数值筛查阈值，不是跳跃高度验收标准。旧候选数判据保留为历史保守诊断，不用于此接口的起跳奖励。所有原始非足部可视网格按刚体合并取凸包，仅压缩支撑顶点，极值高度保持不变；即使原模型未给该部位配置地面响应，穿过地面也使技能失败。

强动作搜索额外筛查机械能：刚体平动、转动、BAM armature 动能与重力势能的增量，不应超过累计正电机做功。正功按逐物理步力矩与平均关节速度积分，忽略负功和摩擦损失得到宽松上界；当前允许量为初始能量与累计正功的 1% 加 0.1 mJ。这是用于排除明显数值能量注入的实验筛查，不构成能量精度验收。数值失败候选不能凭后续腾空得分被选中；真实离地但落地失败的候选也不能交付为空翻。

可通过 `physics_dt` 细化物理步长，但必须同时保持原控制周期和执行器延迟的物理时长，不能在减小步长时暗中缩短延迟。探索可使用 FP32；候选需在 FP64、更小步长及独立引擎下复查。高能量动作尚不具备已确认的动力学精度或可行性结论。

动力学参考可以通过 `reference_trajectory` 加载逐控制时刻的关节目标偏移和高度参考，导出元数据记录对应 SHA-256，推理检查引用文件是否匹配。可选 `landing_feedback` 在首次落地后将躯干 pitch 的 P/D 反馈加到两侧髋、踝位置目标，仍经过同一个 BAM 和执行器延迟，不施加躯干外力。它属于部署控制器的一部分，必须与裸 PPO 分开报告和验证。`reset_joint_noise` / `reset_tilt_noise` 支持后续初态扰动训练；本轮参考 PPO 训练本身仍使用名义初态，扰动回放不是域随机化训练。


## 16. MicroDuck 专用后端与性能实验接口

共享核心定义 `BasicState<B,J,C>`；通用参考为 `<32,32,160>`，MicroDuck 专用状态为 `<16,14,64>`。只压缩存储容量，保持所有实际连杆、关节、网格和接触响应。模型加载检查刚体/关节数量、官方关节名称顺序（接受 `robot/` 前缀），并按可触地形状数乘 4 加自身接触对数验证接触容量上界；容量不足明确报错，不截断接触。

模型保存按原关节顺序的 CSR 刚体邻接表。局部刚体更新只访问相邻关节，复用已经计算的关节角，并只生成当前刚体一侧的 Jacobian；乘子、关节摩擦与收敛残差在一次关节遍历中计算。接触 warm start 只复制实际有效项。这些改动保留原更新表达式与关联项累加顺序。

`CudaBatch(..., specialized=True, shared_memory=False)` 选择专用紧凑全局状态；`shared_memory=True` 为可选实验，将每个环境工作状态协作拷贝到共享内存，并在 chunk 结束写回。共享内存路径不减少迭代或接触，但可能降低 GPU 常驻线程块数量，因此不得假定一定更快。通用后端保留用于回归和消融，专用后端是否成为训练默认值由实际验证决定。

编译开关 `DUCK_NATIVE_FLOAT_MATH=1` 是独立的精度/性能实验：仅 FP32 的角度 wrap、SO(3) 系数和两处常量表达式使用 float 重载；默认 0，FP64 保留原表达式。远端入口 `--native-float-math` 将该设置写入运行 manifest 并在编译前导出。它可能改变舍入，必须与原数学二进制做独立轨迹对照；同一开关下的专用/通用等价不能替代此检查。

`scripts/validate_microduck_specialized.py` 在两精度下逐物理步比较状态、诊断、接触力及广义负载，覆盖动态目标、扰动、释放、显式电机、部分重置、跨 stream 和坏环境恢复；通过后才进行热身和交替顺序吞吐计时。具体覆盖范围、是否实际发生自身接触及吞吐结论以运行报告和开发路径为准。

`DUCK_UNROLL_SMALL_MATRICES=1` / 远端 `--unroll-small-matrices` 仅给固定 6×6 stamp/Cholesky 小循环加展开提示，默认 0，不改变公式。旧跨二进制比较工具及其结果已归档；相关历史验证见开发路径，不能将工具执行完成解释为物理精度通过。
