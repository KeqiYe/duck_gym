# MicroDuck 引擎开发路径

本文件统一记录开发顺序、阶段状态、待办与验收要求。稳定背景见 [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)，数学与接口设计分别见 [AVBD 求解器](ARTICULATION_SOLVER.md) 和 [技术路线](TECHNICAL_PLAN.md)。

## 1. 当前进度与推进规则

项目背景及主线已建立，开发实现尚未开始。接下来从完整资产显示与 CPU/CUDA 基础验证入手。

- 完成阶段时附上代码位置、运行命令和验证结果；文档中已有设计不代表功能已实现。
- 每阶段先确定具体容差、时间步与测试条件，再据结果验收，不预设未经验证的性能数值。
- CPU 路径可在 Mac 本地运行；GPU 路径遵守 [先同步、再远端编译运行](REMOTE_EXECUTION.md) 的约定。
- M1 资产显示和 M2 基础验证相互独立，两者都应在完整 MicroDuck 求解前完成；后续依次推进。

## 3. 各阶段交付与验收

### M1 资产与静态显示

导入固定版本 MJCF、网格与材质，保留来源和许可。解析刚体层级、局部变换、关节轴与初始姿态，建立资产 ID 映射。实现 Mac 本地静态查看和关节交互。

验收：外观网格和材质加载完整，正面、侧面、斜视角能辨认 MicroDuck；缺件及引用错误显式报告；支持旋转、缩放、重置视角与碰撞叠层；保存对照画面。此阶段的运动学展示不代表已实现物理求解。

### M2 工程与单刚体基础

建立原生 C++/CUDA 构建、基础配置和同步运行入口，检查远端主机与工具链。实现刚体状态、惯性、坐标变换、AVBD 六维局部块、自由平移旋转和外力矩。

验收：CPU 本地与 CUDA 远端均实际构建运行；单刚体对解析或独立数值结果正确。CPU FP64 作为参考，CPU/CUDA 同精度对照区分实现与精度误差。用最小缓冲区验证 PyTorch 互操作、生命周期和异步同步。

### M3 关节与电机

实现 hinge 约束、增广拉格朗日乘子与惩罚调度、关节角速度提取、单边限位及受限力矩电机。用双摆和浮动关节链验证。

验收：锚点和轴向误差、限位残差、力矩上限及作用反作用符合预定标准；测量时间步与迭代数对结果的影响；CPU/CUDA 路径一致。

### M4 接触与摩擦

实现接触生成与稳定标识、法向单边约束、摩擦、缓存管理及一致的 AVBD 时间推进。接触图变化后检查并行块调度仍无冲突。

验收：落体、静态承重、滑块和斜面测试通过；检查穿透、载荷、摩擦和能量变化；接触新增/消失时无失效缓存。区分积分耗散和未收敛迭代误差。

### M5 MicroDuck 单 CPU env

组合资产、关节、电机、接触、控制与重置，形成 `num_envs=1` 的完整 CPU 环境，接入本地查看器。

验收：Mac 本地显示真实求解状态；支持暂停、单步和重置；多点足底接触、单脚支撑和姿态控制符合预定误差；关闭渲染仍可推进仿真。

### M6 CUDA 批量环境与 rsl-rl

实现独立环境批维、观测/动作、奖励、终止/超时、随机化（范围按任务确定）和逐环境重置，接入锁定版本的 rsl-rl。GPU 训练无窗口运行。

验收：环境间无物理或缓存耦合，无 NaN；观测和动作的顺序、单位、缩放与控制周期正确；短训练、checkpoint 保存加载和恢复通过。性能包含求解、接触、重置与训练数据交互，不只计单个 kernel。

首个目标行为和评价指标须在本阶段任务定义前明确。短训练可运行仅代表流程连通。

### M7 本地推理与行为基线

将训练模型、观测归一化统计和必要配置带回 Mac，在 CPU 单 env 中推理并显示运动。按选定行为及固定评估条件记录结果。

验收：模型加载与 CPU 推理正确，训练/推理的资产、观测和动作约定一致；本地完整显示策略行为；行为指标达到事先约定的标准。可视化不依赖远端持续传输姿态。
